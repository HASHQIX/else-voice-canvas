# Contracts v1

JSON Schema files are the wire contracts for model output. Context/IDs identifying the destination are attached by trusted server code, not requested from the LLM. Use schema content in Responses API `text.format` as `json_schema`, `strict: true`; validate again on the server. Runtime must handle refusal and incomplete output.

All object properties are required; optional values use `null`. Array/string limits and domain semantics are deliberately checked by the domain validator, not only by the provider subset of JSON Schema. Typescript interfaces are reference types; verify schema/type consistency when generating real application types.

## Required domain checks

- Preview: ≤3 items; slot unique; title ≤80 chars, body ≤320; valid current source quote; no committed mutation; epoch rules in the specification.
- Final: ≤8 statements, ≤10 links, ≤2 issues; titles ≤80, bodies ≤600, assistantText ≤600 chars; question ≤220 chars, 2–3 options except a genuinely open clarification (0 options); each option label ≤60 chars. UI appends Other/Unknown/Skip, they are not invented by the LLM.
- All refs unique and resolve either within this plan or the current snapshot. `targetId` belongs to the current branch. `focusRef` and question target resolve similarly.
- No source quote from another owner/project. Every source must exist verbatim after whitespace normalization. User-derived selected statements need a current user source. Agent-suggested content is proposed/unverified.
- `origin`, `evidence`, `freshness`, UUID, coordinates and revision are assigned by server policy. The LLM cannot declare a claim verified.
- LLM issues are gap/tension. Contradiction requires deterministic computation performed separately; absence of a field alone is not a contradiction.
- Dependency convention: source is foundation, target is dependent. Navigation edges form an acyclic tree and are generated by the UI/domain controller, not confused with these semantic links.
- `branchIntent.create`: sourceBranchId=current branch, forkNodeId exists, targetBranchId=null; route plan mutations into a NEW snapshot. Atomic fork+changes. exploreNow only after explicit instruction to explore.
- `switch_view` / `set_main`: targetBranchId existing owned branch, sourceBranchId=current branch, forkNodeId=null. No statements/links/issues in the same plan; perform navigation first, regenerate analysis for new context if needed.
- `intent` hold/finish/defer controls conversation; it never silently deletes data. Locked target needs an explicit addressed user command; no inference-based unlock.
- Textual assistant acknowledgement must agree with successfully committed changes. On commit failure do not play success text.
- Preview may accept compatible earlier snapshots as specified. Final requires matching branch revision and frozen source hash. operationId is idempotent; server rechecks ownership and budget.

## Example validation

From the handoff root: `python contracts/validate_examples.py` (requires `jsonschema`). This checks example syntax and source linkage, NOT API availability, quality, app performance or security.
